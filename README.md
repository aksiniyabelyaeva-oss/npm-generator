# НПМ-генератор для АГР
Автоматическая сборка низкополигональных моделей зданий по исходным данным заказчика.

## Как запустить

```
python src/run_project.py project_01                 # весь конвейер
python src/run_project.py project_01 --from openings # начать с шага
python src/run_project.py project_01 --no-blender    # без Blender
```

Шаги: контур с топоплана → ручные значения → пристройки → поиск окон →
окна до внешней рамы → оценка по разметке → проёмы на стенах →
`preview.blend` (наша модель + сданная НПМ) → сравнение со сданной НПМ →
материалы из сданной НПМ в частную библиотеку → **генерация НПМ** (`npm_generator.py`) →
**проверка НПМ** (`validate_npm.py`) → **похожесть на сданную** (`visual_compare.py`).

Готовая НПМ — `data/<имя>/output/`: FBX 7.4 (двоичный, метры, ось Z, текстуры встроены),
атлас `textures/T_<имя>_Main_{d,n,r,m}_1.png` 2048×2048 и отчёт проверки `validation.txt`.

- Настройки проекта (файлы, слои, значения, которые пока задаются вручную) — `projects/<имя>.json`.
- Данные проекта — `data/<имя>/` (в git не попадают). Картинки — `data/<имя>/plots/`.
- Путь к Blender — переменная окружения `BLENDER`, по умолчанию путь Steam.
- Эталон разметки окон `windows_checked.json` конвейер только читает. Правки — через
  `src/fix_item.py`, они пишутся в журнал `gold_fixes.json`.

## НПМ (project_01)

| | Наша | Сданная |
|---|---|---|
| Объект / материал | `SM_…_Main` / `M_…_Main_1` | то же |
| Текстуры | атлас 2048, карты d/n/r/m, однотонные плитки | атлас 2048, d/n/r/m |
| Треугольников | 1 106 | 17 019 (рекомендуется до 15 000) |
| Формат | FBX 7400, UnitScaleFactor 100, ось Z | то же |
| Проверка `validate_npm.py` | пройдена, 0 предупреждений | пройдена, 2 предупреждения |

Валидатор проверяет: имя файла, двоичный FBX 7.4, метры, ось Z, имена `SM_/M_/T_` и суффиксы,
треугольники и их число, вырожденные и дублирующиеся грани, UV в 0…1, привязку в МСК
и к нулю здания, размер и формат текстур. Сданная модель его проходит — значит, он не строже,
чем реальная приёмка. Требования — по пересказу методических рекомендаций
(https://smway.ru/metodicheskie-rekomendacii-agr-3d-modeli/), уточнить по первоисточнику.

## Библиотека материалов

Материалы три видов, в одном формате (`material.json` + карты d/n/r/m):

| Откуда | Где | В git |
|---|---|---|
| Рисует код (`src/textures.py`): доска, фальц, штукатурка, окраска, стекло | `library/materials/` | да |
| ambientCG (CC0) по запросу (`src/cc0.py`): кирпич, камень, бетон… | `data/cc0_cache/materials/` | нет, скачивается сам |
| Сданные НПМ бюро (`src/library_from_npm.py`) | `data/library_private/materials/` | нет |

`library_from_npm.py` режет атлас сданной модели на плитки: делит его по линиям, которые не
пересекает ни один UV-остров, и для каждой плитки считает, какие грани её используют
(стены или кровля, высоты, пикселей на метр). Это готовая разметка «грань → материал».

В настройках проекта (`materials`) каждой роли поверхности (стена 1-го и 2-го этажа, отделка,
цоколь, кровля, пристройки, стекло, дверь, слуховые окна) назначается материал. Если его нет,
берётся материал кода по умолчанию. Генератор собирает из них атлас и кладёт текстуру в
реальном масштабе: вдоль полос (доска, фальц) растягивает, поперёк режет грань по размеру плитки.
Список: `python src/library.py`, каталог публичных — `library/CATALOG.md`.

Материал роли можно задать тремя способами:
```json
"wall1":  {"material": "plaster", "params": {"color": "#A38F7A"}}
"plinth": {"material": "ambientcg:PavingStones131"}
"wall2":  {"search": "red brick"}
```
Для `ambientcg:` и `search` генератор сначала ищет в библиотеке и кэше, и только если там нет —
идёт в API ambientCG, скачивает архив 1K, переводит в наш формат и кладёт в кэш (один раз).
Нет интернета — берёт материал кода и пишет об этом. Вручную: `python src/cc0.py search granite`,
`python src/cc0.py get Bricks104`, `python src/cc0.py import архив.zip`.

## Похожесть на сданную НПМ

`visual_compare.py` рендерит обе модели одной камерой с четырёх углов и считает
**силуэт** (IoU очертаний) и **цвет** (доля мест, где цвет почти совпадает, на картинке,
уменьшенной в 4 раза). Картинки — `data/<проект>/plots/visual_*.png`.

| # | Версия НПМ | Треугольников | Силуэт | Цвет |
|---|---|---|---|---|
| 1 | однотонные плитки, проёмы без рам | 1 106 | 89% | 40% |
| 2 | материалы из библиотеки; рамы, наличники, отливы, пояса, карнизы, свесы, лопатки, вальмы пристроек, козырёк | 3 063 | 89% | 50% |

## Открытые вопросы

- Контур с топоплана на 0.5 м шире стен сданной модели и сдвинут на 0.37 м.
- Высоты пристроек — константа 6.40; у сданной модели пристройки выше, у правой своя кровля.
- Рельеф: низ сданной модели −4.1, у нас цоколь до −0.69; окно подвала NE не размещается.
- НПМ: нет GeoJSON с привязкой и упаковки в архив; нет крыльца со ступенями, труб, рельефа;
  размеры деталей фасада (пояса, карниз, наличники) пока общие — брать из чертежей;
  имя файла и объекта задаётся в настройках (транслитерацию адреса — автоматизировать).
- Соответствие фасадов сторонам света (`FACADE_SIDE`) задано в коде — перенести в настройки проекта.
